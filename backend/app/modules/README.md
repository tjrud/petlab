# 모듈 라이브러리

구조물을 **부품(코드 템플릿)** 과 **조립 모듈(JSON)** 로 나눈다.

- 부품: `app/templates/*.py`. 형상을 직접 만드는 검증된 코드 (은신처, 터널, 경사로, 모래목욕통, 그릇 받침 등).
  부품마다 `anchors()` 로 연결 지점을 낸다.
- 조립 모듈: `app/modules/library/*.json`. 부품들을 연결 지점끼리 이어 붙인 설계도와 바깥에 드러낼 파라미터.
  엔진에서는 모듈 하나가 템플릿 하나처럼 동작한다 (`ModuleTemplate`): 보정·배치·검증·저장·내려받기가 그대로 쓰인다.

## 연결 지점 (Anchor) 규칙

좌표는 부품 `build()` 좌표계 (바닥 Z=0). 부품을 이으면 자식의 연결 지점이 부모의 연결 지점에 **마주 보게**
(법선이 반대, 위쪽이 같게) 붙는다.

- 바닥에 서는 부품의 옆면 연결 지점은 **그 면의 아래쪽 가운데(Z=0)** 에 둔다. 그래야 이어 붙인 부품의 바닥이 맞는다.
- `normal` 은 면 바깥 방향, `up` 은 면 위의 위쪽. 둘 다 단위 벡터이고 서로 수직.
- 위에 얹는 자리는 `top` (normal +Z, up +Y), 밑면은 `bottom` (normal −Z, up +Y).
- 출입구·터널 끝처럼 드나드는 자리는 `port`(통로 폭 mm)를 둔다. 통로 자리는 다른 부품으로 막을 수 없고
  (`passage: true` 로만 이을 수 있다), 아무것도 붙지 않은 통로 자리는 바깥 출입구로 센다.
- 다른 부품이 통로로 이어 붙을 때 뚫어도 되는 벽면에는 `wall_mm`(벽 두께)를 둔다. 통로 부품은 `port_cutter()` 로
  통로 단면 기둥을 내고, 조립할 때 부모 벽을 그 모양으로 뚫는다 (`app/templates/base.cutter_at`).
- `side` 는 그 면이 `features().access_sides` 의 출입 면일 때 그 이름. 이어 붙이면 출입 면에서 빠진다.
- 슬라이드 결합 연결판을 붙일 수 있는 면에는 `mount = (left, right, height)` 를 둔다. 면 좌표 (t, u) 는
  t = up × normal (바깥에서 볼 때 오른쪽), u = up, 원점 = origin 이다. 은신처: 출입구 없는 옆면 전체.
  집: 출입구·연결부·착지판 없는 벽, 높이는 1층 평 지붕이면 외형 높이 전체, 지붕 뚜껑을 씌우면 처마 − SKIRT_MM,
  2층 집은 그중 2층 바닥 높이까지(보수적으로), 창이 있는 면은 창 아래 끝 − MARGIN_MM 까지.
  모래목욕통: 뒤·왼쪽·오른쪽은 면 전체 (높이 = 안쪽 깊이 + 바닥 두께), 앞면은 가로 전체 × 턱 높이. 앞면 연결판은
  늘 경사로 끝나고 경사 끝이 턱 높이에서 벽에 닿으므로 출입 홈(턱 위로 파인 곳)을 덮지 않는다. 앞면에 턱 높이 램프를
  `landing` 으로 슬라이드 결합하면 발판이 턱 윗면 높이에 오고 (발판 끝과 벽 사이는 연결판 경사가 메운 3.7mm 홈),
  모래목욕통 앞면(출입 면)은 이어져 빠지고 램프 입구(`entry`, side="front")가 모듈의 출입 면이 된다.
  모래목욕통 앞면을 출입 면이 없는 부품으로 막지 않는다 (엔진이 막지 않는다: 그릇 받침도 자기 앞면을 출입 면으로 내므로).

## 모듈 JSON

`definition.py` 의 `ModuleDef` 가 형식이다. 첫 부품이 기준(뿌리)이고, 나머지 부품은 모두 한 번씩 이어져야 한다.
부품 파라미터는 상수이거나 모듈 파라미터에 묶는다: `{"param": "width_mm", "scale": 1, "offset": -10}`.
묶은 관계로 부품의 종별 제약(최소 출입구 등)을 모듈 파라미터 제약으로 되돌려 자동 보정한다. 상수로 둔 값이
종별 기준을 어기면 그 종에는 쓸 수 없다는 오류가 난다.

부품 파라미터 이름은 점 표기로 중첩 파라미터를 가리킬 수 있다 (집처럼 부품 모델이 중첩된 템플릿).
상수는 숫자·글·참거짓 또는 글 목록이다. 부품 제약의 field 도 같은 점 표기라 묶은 관계가 그대로 되돌려진다
(중첩 int 필드는 반올림한다). 모듈을 불러올 때(`ModuleTemplate`) 없는 경로나 기본값으로 만들 수 없는 값은 거부한다.
모듈 파라미터의 끝값(숫자는 min·max, choice 는 선택지 하나하나, 나머지는 기본값)으로도 부품 파라미터 범위·선택지를
벗어나지 않아야 한다 (사용자가 고른 값에서 부품 검증 오류로 엔진이 멈추지 않게, 불러올 때 거부한다).

```json
{"id": "house", "template": "house", "params": {
  "roof.kind": "pitched", "ports.sides": ["right"],
  "ports.diameter_mm": {"param": "port_mm"}, "walls.thickness_mm": {"param": "wall_mm"}}}
```

### 모듈 파라미터 범위 관계 (`limits`)

자식 부품이 부모 면 안에 들어가게 하는 것처럼 모듈 파라미터끼리의 관계를 둔다 (은신처 세로 ≥ 그릇 받침 외형 폭 + 여유,
은신처 높이 ≥ 램프 높이, 램프가 프린터에 들어가는 경사 등). `min`·`max` 는 숫자이거나 다른 모듈 파라미터에 묶은 값
(`scale × 파라미터 + offset`, scale > 0, 1차식만). 둘 중 하나는 있어야 한다.

```json
"limits": [
  {"param": "depth_mm", "min": {"param": "bowl_mm", "scale": 1, "offset": 10},
   "reason_ko": "그릇 받침이 은신처 옆면 안에 들어가도록 세로를 그릇 받침 폭보다 넓혔습니다",
   "reason_en": "Made the hideout deeper than the bowl holder so it fits on the side face"}
]
```

- `ModuleTemplate.constraints()` 가 limit 마다 `param` 의 `ParamConstraint` 를 내서 자동 보정이 `param` 을 올리거나 내린다.
  묶인 쪽(`bowl_mm`)은 움직이지 않는다. 보정 문구에는 `reason_ko` 가 붙고, `reason_en` 은 번역 카탈로그에 더해진다.
- `param` 의 범위(ParamDef min·max) 밖이어야만 맞출 수 있는 쪽(위 예에서 bowl_mm + 10 > depth_mm 최대)은 제약으로 내지
  않고 `rule_issues` 가 "…자동으로 맞출 수 없습니다" 오류로 남긴다 (사용자가 묶인 쪽을 줄여야 한다).
- 사슬: 자동 보정(`clamp_params`)은 패스마다 그 패스 시작 값으로 제약을 다시 계산하므로 한 패스에 한 고리씩 따라간다
  (부품 제약이 출입구를 올림 → 그릇 ≥ 출입구 + 30 → 세로 ≥ 그릇 + 10 은 세 패스에 걸쳐 맞춰진다). 사슬 길이는
  `LIMIT_CHAIN_MAX`(4) 이하만 받는다 (`MAX_PASSES` 8 안에 끝나게).
- 불러올 때 검사: 파라미터가 있고 숫자(choice 아님)인지, 자기 자신에 묶지 않았는지, 사슬 길이, 기본값에서
  min ≤ max 이고 기본값이 그 범위 안인지 (아니면 기본 설계부터 보정이 값을 바꾼다).
- 비선형 관계(램프 길이 = 높이 ÷ tan 경사)는 1차식으로 안전하게 근사한다: 위로 볼록한 함수는 접선이 늘 위에 있다.

### 결합 방식 (`joins[].mount`)

- `"fused"` (기본): 한 덩어리로 붙인다. `passage: true` 면 통로로 벽을 뚫는다.
- `"slide"`: 따로 출력해 끼운다. 한 덩어리로는 서포트 없이 출력할 수 없는 조합(은신처는 뒤집어, 그릇 받침은 바로
  세워 출력한다)에 쓴다. 옆면끼리만(두 연결 면이 세로, 위쪽 +Z, spin 0), 통로와 함께 쓸 수 없다.

```json
{"parent": "house.right", "child": "bowl.back", "mount": "slide"}
```

슬라이드 결합 (`assembly.py` 의 `slide_plan`·`plate_solid`·`slot_cutters`·`tongue_solid`):

- 부모 면에 두께 `PLATE_MM`(4mm) 연결판을 붙인다: 가로 = 자식 외곽 폭, 높이 = min(자식 높이, 붙일 수 있는 높이).
  자식은 연결판 바깥에 놓인다 (연결판에 OVERLAP_MM 묻힘). 연결판 끝이 부모 꼭대기가 아니면 윗면은 벽 쪽으로
  올라가는 50° 경사로 끝난다 (뒤집어 출력해도 오버행이 아니고, 자식 윗모서리와 벽 사이에 홈이 남지 않는다).
- 출력 파트에서만 연결판에 세로 도브테일 홈(위아래가 트임, 안쪽이 넓다)을, 자식 뒷면에 틈새 0.25mm 의 혀를 낸다.
  자식을 위에서 밀어 내리면 끼워지고 옆·바깥으로는 빠지지 않는다. 100mm 마다 하나 (최소 하나).
  혀는 자식 출력 파트 가운데 연결판에 가장 넓게 닿는 파트에 붙는다 (물병 거치대는 받침판이 아니라 물병 컵).
  출력 자세에서 아래를 보는 혀 끝은 경사로 깎는다.
- 조립 형상(`build()`)은 부모 ∪ 연결판 ∪ 자식 한 덩어리 (홈·혀·틈새 없음). 출력 파트(`print_parts()`)는 fused 결합으로
  이어진 부품 묶음마다 하나 (기준 묶음 "본체", 나머지는 부품 이름) + 부품이 따로 출력하는 파트. 홈·혀가 있는 묶음은
  도브테일이 세로로 서는 사용·뒤집기 자세 중 서포트가 적은 쪽으로 출력한다.
- 연결판보다 높은 자식은 연결판 위로 벽과 뒷면 사이에 `PLATE_MM − OVERLAP_MM`(3.7mm) 틈을 남긴다. 햄스터 끼임 안전
  틈(4mm)보다 작게 두께를 정했고, 종별 기준으로 끼임 위험 구간이면 오류다.
  이 틈은 상수로 두지 않고 잰다 (`assembly.plate_gaps`): 연결판 높이 위 자식 뒷면의 격자점마다 벽 쪽으로 광선을 쏘아
  자식이 아닌 출력 파트(벽·연결판 경사·지붕 뚜껑)에 닿는 거리. 그래서 경사·둥근 지붕 집의 처마 쪽 면(앞·뒤)에
  처마보다 높은 자식(물병 거치대 등)을 붙이면 지붕 경사면과 자식 뒷면 사이에 위로 벌어지는 쐐기 틈이 잡혀 오류가 된다
  (지붕에서 미끄러진 다리가 끼는 곳). 박공 면(왼쪽·오른쪽)은 박공판이 스커트와 같은 면이라 틈이 벽 두께만큼 좁다.

이름·설명은 한국어와 영어를 함께 쓴다 (`name_ko/name_en`, `description_ko/description_en`). 응답 번역 카탈로그에 더해진다.

**공개한 모듈 파일은 형상이 바뀌게 고치지 않는다.** 저장된 설계가 모듈 key 로 다시 만들어지기 때문이다.
바꾸려면 새 key(`_v2`)로 새 파일을 만든다.

## 검증

조립 모듈도 일반 구조물과 같은 검증을 받는다 (닫힌 메시, 벽 두께, 오버행, 출력 크기, 케이지 배치, 출입구·통로 크기,
끼임 틈). 여기에 더해:

- 출입구·터널 끝을 다른 부품으로 막으면 오류
- 은신처처럼 드나드는 공간이 있는 모듈(`enclosure: true`)은 바깥 출입구 수를 종별 최소 개수와 비교
- 서로 잇지 않은 부품 사이 틈이 끼임 위험 구간이면 오류
- 출입구·터널 끝(port 가 있는 부모 연결 지점)에 통로로 이은 부품이 개구부를 다 덮지 못하면 오류: 부모 개구부 단면 기둥
  (부모 면에서 바깥으로 벽 두께만큼) − 자식 형상 − 자식 통로 단면 기둥이 1mm³ 보다 크면 바깥으로 뚫린 틈이 남는다
  (뾰족 아치 집 출입구에 둥근 아치·관·네모 터널, 둥근 아치 은신처 출입구에 관 등). 자식 벽이 개구부를 다 덮고 통로만
  좁으면 벽 속에 막힌 턱이 남을 뿐이라 세지 않는다 (`assembly.passage_leftover`). 남은 곳을 부모 면에 비춘 모양의
  가장 넓은 폭(내접원 지름, `assembly.leftover_width`)이 0.5mm 이하면 출력하면 메워지는 실금이라 세지 않는다
  (예: 60mm 은신처 출입구에 56mm 뾰족 아치 터널은 아치 어깨에 0.3mm 실금만 남는다)
- 따로 출력하는 파트끼리(본체·지붕 뚜껑·층판·슬라이드 결합 묶음) 1mm³ 넘게 겹치면 오류 (예: 경사 지붕 집 벽에 처마 −
  SKIRT_MM 보다 높은 램프를 붙이면 지붕 뚜껑 스커트와 겹친다)
- 슬라이드 결합: 연결판을 붙일 수 없는 면, 붙일 수 있는 영역보다 넓거나 벗어난 자식(면 밖으로 튀어나오면 모서리에
  홈이 남는다), 바닥에 서지 않은 자식, 도브테일을 낼 수 없을 만큼 좁거나 낮은 뒷면, 연결판 위 끼임 틈은 오류
- 창(`Opening.kind = "window"`)은 끼임 위험 구간 크기면 오류
- 출력 자세는 여섯 방향을 눕혀 보고 서포트가 가장 적은 쪽을 고른다 (`ModuleTemplate.print_rotation`). 부품이 따로 출력하는 파트(집의 지붕 뚜껑 등)는 그 부품이 정한 자세 그대로 둔다
- 형상 검사는 파라미터별로 한 번만 계산해 둔다 (`ModuleTemplate._cached`)

- 모듈 limits 를 자동 보정으로 맞출 수 없으면 (묶인 쪽 값 때문에 param 범위 밖이어야 하면) 오류

`tests/test_modules.py` 가 라이브러리의 모든 모듈을 기본값·크기 범위 끝값으로 만들어 이 기준을 확인한다.
출력 크기도 확인한다: 기본값·크기 끝값을 햄스터 크기마다 자동 보정한 값에서 출력 파트마다 출력 자세로 기준 프린터
(220×220×250mm, `rules/printing.yaml`) 안에 들어가야 한다 (엔진의 `check_build_volume`, 판 위에서 90° 돌려 놓기 포함).
엔진에서는 경고(`exceeds_build_volume`)지만 라이브러리 모듈은 넘지 않게 만든다. 공개한 `hideout_with_tunnel` 은 은신처와
터널이 한 덩어리라 골든 햄스터 기본값(세로 110 + 터널 120)부터 넘는다 (형상을 바꿀 수 없어 `KNOWN_OVERSIZE` 로 둔다).
